</ol><hr><h2 id="overview">1. 📖 Overview</h2><p>
  <b>Supermarket Sales SLM</b> is a small language model project designed to answer questions about supermarket sales data.
  The project uses a sales dataset containing 15,000 transaction records and converts the information into a structured
  question-and-answer dataset. The open language model <b>SmolLM2-135M-Instruct</b> is then fine-tuned on these examples
  so that it can respond to retail analytics questions in natural language.
</p><p>
  Instead of manually filtering spreadsheets or writing queries, a user can ask questions such as
  <i>“Which product line generated the highest revenue?”</i> or
  <i>“What is the total sales amount for Yangon?”</i>
  The fine-tuned model generates an answer based on patterns and facts learned from the prepared dataset.
</p><p><b>Important:</b> This repository contains the dataset preparation, training and evaluation code, along with the generated
training, validation and test data. The trained model checkpoint is produced when the training script is run; it is not
included in the repository by default.</p><h2 id="objectives">2. 🎯 Project Objectives</h2>
<ul>
  <li>Prepare supermarket transaction data for language-model training.</li>
  <li>Generate natural-language questions and reference answers from sales records.</li>
  <li>Fine-tune a compact pre-trained language model for a focused retail analytics task.</li>
  <li>Enable users to ask sales-related questions using everyday language.</li>
  <li>Evaluate the model on a held-out test set and compare it with the original base model.</li>
  <li>Provide a reproducible workflow for dataset generation, training and evaluation.</li>
</ul><h2 id="features">3. ✨ Key Features</h2>
<ul>
  <li><b>Natural-language question answering:</b> Ask questions about sales without manually writing spreadsheet formulas.</li>
  <li><b>Retail analytics topics:</b> Supports questions about revenue, product lines, branches, cities, quantities, transactions,
      payment methods, ratings and simple calculations represented in the generated dataset.</li>
  <li><b>Compact model:</b> Uses SmolLM2-135M-Instruct, a relatively small model compared with large general-purpose language models.</li>
  <li><b>Structured training data:</b> Uses separate training, validation and test files.</li>
  <li><b>Reproducible dataset generation:</b> The dataset-building script uses a fixed random seed.</li>
  <li><b>Evaluation script:</b> Measures numeric answer accuracy and can compare the fine-tuned model with the base model.</li>
  <li><b>Hugging Face integration:</b> Includes a script for publishing the generated dataset to the Hugging Face Hub.</li>

<ul>
  <li><b>Dataset composition:</b> The first 1,000 rows of the source CSV match the public Kaggle Supermarket Sales dataset; the remaining 14,000 rows are synthetic additions. Treat results as experiments on this prepared dataset, not as evidence about every real supermarket.</li>
  <li><b>Limited date range:</b> The data represents January to March 2019 only.</li>
  <li><b>Small model:</b> A 135-million-parameter model has limited capacity and may produce incorrect or invented figures, especially for questions outside the training data.</li>
  <li><b>Not a live analytics system:</b> The model does not automatically connect to a live supermarket database. Its answers are based on the information represented in the prepared dataset.</li>
  <li><b>Financial interpretation:</b> The source data's gross-income and tax fields have a fixed relationship. The resulting margin values should not be treated as a realistic measure of business profitability.</li>
  <li><b>Hardware:</b> Training speed and memory requirements depend on the machine, PyTorch build and available accelerator.</li>
</ul><h2 id="future">14. 🚀 Future Improvements</h2>
